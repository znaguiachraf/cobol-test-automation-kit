Overview

What the kit does, end to end.

ConfigureCompiler, flags, paths, timeouts in config/kit.config.json
BuildCompiles your COBOL source with the configured compiler
TestFeeds each test's input on stdin and compares the output
ReportResults page plus a standalone, printable HTML report

Every result shown comes from real process output: exit codes, stdout, stderr. A test that did not execute is shown as NOT RUN, never as PASS.

1Prerequisites

You need Python 3 and, to actually compile COBOL, GnuCOBOL.

Check what you have 
python3 --version
cobc --version

Install GnuCOBOL (only if cobc is missing)

SystemCommand
macOS (Homebrew)brew install gnucobol
Debian / Ubuntusudo apt install gnucobol
Fedorasudo dnf install gnucobol
No compiler yet?The app still starts. Validation will clearly report "Compiler 'cobc' not found" and runs will show the build as an error with every test NOT RUN.

There are no Python packages to install. The kit uses only the standard library.

4Configure & validate

The defaults already point to the sample program, so you can just validate.

FieldDefaultMeaning
Compiler adaptergnucobolHow the build command is assembled
Compiler executablecobcName on PATH or a full path
Compiler flags-x -free -WallExecutable, free-format source, all warnings

  1. Click Validate configuration. This checks paths, the compiler and the test file without running anything.
  2. The Validation panel lists each check as OK, WARN or ERROR. WARN for the build/report folders just means "will be created on first run".
  3. If you changed anything, click Save configuration. Runs always use the saved config, and the page warns you about unsaved changes.
Paths must stay inside the project folder.Relative paths are resolved from the project root. Anything resolving outside it (e.g. ../other) is rejected. Paths with spaces are fine.

5Run the tests

Click Run tests on the Configuration page (or Run again on the Results page). The kit will:

  1. Validate the saved configuration.
  2. Delete its own previous build of the program, so a failed compile can never run an old binary.
  3. Compile, e.g. cobc -x -free -Wall -o build/PREMCALC samples/src/PREMCALC.cbl.
  4. Run each enabled test: send input + newline on stdin, capture stdout/stderr/exit code, compare.
  5. Save the run to runs/<run_id>.json and write reports/report-<run_id>.html.

A progress banner shows the current step. Expected result for the sample:

PASSED WITH SKIPS: 14 passed, 0 failed, 0 errors, 1 not run (15 total) TC-014 is disabled on purpose to show how a pending business rule appears as NOT RUN.

6Read the results

The Results page shows the latest run (pick older ones in Run history):

  • Run summary: run ID, start/end time, compiler version, platform, and counts.
  • Compilation: status, exit code, exact command, and expandable compiler stdout/stderr.
  • Test cases: ID, description, input, expected vs actual, status, duration, and the reason for any failure.
  • Program output per test: raw stdout/stderr of every executed test.

Status meanings

FAILExecuted, but output or exit code differed from expected

7Open the HTML report

Click Open HTML report on the Results page. The report is a single file in reports/ with the run and environment info, configuration summary, counts, compiler output, the full test table, failure diagnostics and a list of limitations / tests not executed.

  • Print it or use Save as PDF from the browser; print styles are built in.
  • It loads nothing from the internet and contains no scripts; all program output is escaped.
  • Local paths are shortened to <project> and ~.

An example is included: docs/sample-report.html (labelled SAMPLE).

8Use your own COBOL program

  1. Put your source in a folder inside the project, e.g. myprog/src/CLAIMCHK.cbl.
  2. Make sure the program follows the stdin → stdout interface: read its input with ACCEPT, print results with DISPLAY, and set RETURN-CODE for error exit codes.
  3. Create a test file, e.g. myprog/tests/claimchk_tests.json (see next step).
  4. On the Configuration page set Source directory myprog/src, Source file CLAIMCHK.cbl, Test cases file myprog/tests/claimchk_tests.json.
  5. Fixed-format source? Change the flags from -x -free -Wall to -x -Wall (or -x -fixed -Wall).
  6. Save, Validate, then Run tests.
Public repository?Use only synthetic programs and data. Never commit employer/client code, credentials or proprietary configuration.

9Write test cases

myprog/tests/claimchk_tests.json 
{
  "suite": "CLAIMCHK validation",
  "default_timeout_seconds": 5,
  "tests": [
    {
      "id": "TC-001",
      "category": "normal",
      "description": "Valid claim is accepted",
      "input": "C1001,250.00",
      "expected": { "stdout": "STATUS=ACCEPTED", "exit_code": 0 },
      "compare": "exact"
    },
    {
      "id": "TC-002",
      "category": "invalid",
      "description": "Negative amount is rejected",
      "input": "C1002,-5",
      "expected": { "stdout": "ERR", "exit_code": 4 },
      "compare": "contains"
    },
    {
      "id": "TC-003",
      "category": "normal",
      "description": "Rule waiting for business confirmation",
      "input": "C1003,9999.99",
      "expected": { "stdout": "STATUS=REVIEW" },
      "compare": "exact",
      "enabled": false,
      "skip_reason": "Threshold not confirmed yet"
    }
  ]
}
FieldRequiredNotes
idyesUnique; letters, digits, _ - . (max 40)
descriptionyesShown in results and report
inputnoSent to stdin with a newline appended
expected.stdoutfor exact / contains / regexText, substring or regular expression
expected.exit_codefor exit_codeIf set, also checked in every other mode
compareno (default exact)exact, contains, regex, exit_code
timeout_secondsnoOverrides the default timeout
enabled, skip_reasonnofalse → NOT RUN with the reason shown
categorynoFree text, e.g. normal / boundary / invalid / regression

Output normalisation before comparing: CRLF → LF, trailing spaces removed on each line (COBOL DISPLAY padding), leading/trailing blank lines dropped.

Good practiceDerive expected values from the business rules, not by copying the program's output. Cover normal, boundary, invalid and regression cases.

10Change the compiler (no code changes)

Another GnuCOBOL installation

Set Compiler executable to the full path, e.g. /opt/gnucobol-3.2/bin/cobc, then Save and Validate.

Any other command-line compiler: the generic adapter

Select adapter generic and write the complete flags, using the placeholders {source} and {output} as whole arguments:

Compiler flags field 
-x -free -o {output} {source}

The flags field is split like a shell command line (quotes group words: -I "copy books"), but it is never run through a shell: no variables, wildcards, pipes or ;.

A very different build process (JCL submit, multi-step link, DB2 precompile) needs a new adapter class in app/compilers.py: implement check_args and build_command and register it in ADAPTERS.

11Command line (no browser)

python3 -m app validate          # check config, paths, compiler, test file (runs nothing)
python3 -m app run               # build + test with the saved config, write the report
python3 -m app report RUN_ID     # re-render the report of a recorded run
python3 -m app report RUN_ID --sample --out docs/my-sample.html

python3 -m app run exits with 0 for PASSED / PASSED WITH SKIPS and 1 otherwise, so it fits in CI.

Run the kit's own tests

python3 -m unittest discover -s tests -t . -v

Tests that need GnuCOBOL are skipped automatically when cobc is not installed.

The project includes .claude/skills/cobol-test-workflow/SKILL.md. Start Claude Code in the project root and ask, for example:

The skill makes Claude:

  • run only the documented commands and read the real run records;
  • label proposed tests as confirmed (you stated the rule) or inferred (derived from code);
  • never change expected values, disable tests or edit COBOL to hide failures; fixes are proposed for your review.

Troubleshooting

SymptomFix
"Compiler 'cobc' not found"Install GnuCOBOL or enter the full path to cobc.
BUILD FAILED with format errorsFlags don't match the source format: -free for free format, -fixed or none for fixed.
libcob errors when tests runCompiler/runtime mismatch. Check with cobc --info.
Test ERROR "Timed out"The program waits for more input or loops. Check the stdin protocol; raise timeout_seconds only if it is genuinely slow.
"resolves outside the project directory"Keep all paths inside the project folder.
"You have unsaved changes"Click Save configuration (runs use the saved config) or Discard changes.
403 "Host not allowed"Open the app via 127.0.0.1 or localhost.
Port 8765 in usepython3 -m app serve --port 9000

Safety notes

  • Intended for local, trusted, single-user use. It binds to 127.0.0.1 by default. Do not deploy it as a public server.
  • There is no endpoint that runs arbitrary commands; processes are started from argument lists with timeouts.
  • Whoever can edit the config chooses the compiler executable. Treat the config as trusted input.
  • The kit never edits your COBOL source or expected results to make tests pass.

First-run checklist

  • Start the app with python3 -m app and open the Configuration page.
  • Validate; if GnuCOBOL is missing, confirm the app says so clearly.
  • Run the sample tests; expect 14 passed and 1 not run.
  • Open the Results page and the HTML report.
  • Change an expected value in the test file, run again, and confirm it stays FAIL. Then revert it.
  • Change the compiler executable or flags, save, and confirm the new command is used.
  • Add screenshots and a demo GIF to the README before sharing.
